# 安卓定时开售与抢票流程优化设计

## 背景与目标

当前安卓 worker 按顺序执行城市、购买入口、票档、数量、观演人和提交操作。普通失败会等待两秒并重建 Appium 会话；按钮等待使用默认 500ms 轮询；部分点击需要额外读取元素坐标；数量点击异常不会阻止后续提交。

本设计在不改变票档优先级、观演人配置和自动提交开关语义的前提下，缩短从开售到首次有效提交的耗时，并避免在页面状态不明确时继续下单。

成功标准：

- 用户可填写本机开售时间，提前启动 worker；留空时立即执行。
- 到点后只点击明确可购买的按钮，不把预约、缺货或售罄当作可购买。
- 普通页面失败在当前步骤处理，只有驱动或会话异常才重建 Appium 会话。
- 数量、观演人和提交入口均有明确校验，提交按钮最多触发一次。
- 日志包含各阶段耗时和首次提交耗时。

## 范围

包含：

- 安卓配置增加可选 `sale_time`。
- Web 安卓表单增加开售时间输入、保存和回显。
- worker 增加会话预热、票档预加载、定时等待、可购买状态检测、局部等待、数量校验和分阶段耗时日志。
- 普通点击减少一次元素坐标读取，优先通过元素 ID 执行 `mobile: clickGesture`。
- 配置、worker、API 和 Web 页面的自动化验证。

不包含：

- 独立调度服务、多任务队列或跨进程定时任务持久化。
- 修改现有票档区域、价格排序、观演人去重和自动提交确认规则。
- 绕过验证码、风控、服务器排队或大麦下单接口。
- 未连接真实安卓设备时的真机成功承诺。

## 配置与页面

`DEFAULT_ANDROID_CONFIG` 新增空字符串 `sale_time`。配置校验接受空字符串或不带时区的本机 ISO 日期时间，分钟和秒精度均允许；其他类型、无效日期和带时区值返回可操作的配置错误。保存时使用规范化 ISO 字符串，旧配置不填写该字段时保持原行为。

Web 表单使用可选 `datetime-local` 输入，说明“按本机时间执行，留空立即开始”。读取、保存和回显均复用现有安卓配置链路，不增加新 API。

## 启动与定时流程

1. 用户保存配置并点击开始，现有环境检查和自动提交确认保持不变。
2. worker 创建 Appium 会话并应用现有性能设置。
3. 在城市准备和定时等待之前加载、校验票档缓存。缓存缺失、区域不匹配或格式无效时立即失败，避免无效等待。
4. 若当前已在票档页，跳过城市和购买入口准备；否则完成城市选择。
5. `sale_time` 为空或已经到点时直接继续。未来时间使用本机墙上时间计算初始间隔，再以单调时钟休眠，避免等待期间系统时间调整造成重复或漏掉触发。长等待每 60 秒读取一次当前 Activity 作为会话保活和断连检测，避免超过 Appium `newCommandTimeout` 后在开售前静默失效。
6. 定时等待期间不发送购买点击。现有停止任务通过终止 worker 进程生效。

## 可购买状态与购票流程

定时模式使用 100ms 轮询和 30 秒上限等待购买入口。只有满足以下条件的元素才可点击：

- 文本命中元素本身，或其最近的可点击祖先为 enabled 且 clickable。
- 文本明确表示购买、抢购、预订或抢票。
- 文本不包含预约、缺货、售罄、无票或缺票。

页面已展示票档容器时直接继续，不重复点击购买入口。30 秒内未出现有效按钮则返回失败，不点击预约入口。非定时立即模式沿用快速查找，但也必须拒绝明确的不可购买文本。

票档选择继续使用已缓存候选顺序、可购买判断和价格复核。普通点击找到元素后直接以其元素 ID 执行手势，不再读取坐标。观演人选择继续逐人读取复选框状态，点击后重新读取并确认。

数量设置后从现有 `layout_num` 区域读取明确数字并与观演人数比较。无法读取明确数量或数量不符时停止，不猜测数量，也不进入观演人和提交步骤。该行为需要真机验证现有容器是否能提供数量文本。

提交订单保持配置开关控制。提交按钮未找到、状态不明确或点击异常时返回失败，不通过备用循环连续补点。每次流程最多触发一次提交手势；一旦已经发出提交手势，无论后续返回成功、失败还是会话异常，都不得通过外层重试再次提交。

## 重试与生命周期

元素未出现、按钮未就绪等页面状态由当前步骤的显式等待处理。票档售罄继续尝试缓存中的下一候选，观演人勾选后重新读取状态。

`run_ticket_grabbing` 不再在每次普通失败后销毁会话。`run_with_retry(max_retries=3)` 保留公开调用方式，但仅对 Appium/WebDriver 会话异常重建驱动；配置错误、票档不可买、数量不符、观演人未选中等业务失败直接结束，不进行整段重试。若会话异常发生在提交手势之后，则停止重连并提示用户到大麦 App 核对订单，避免重复下单。最终统一关闭驱动一次。

日志使用单调高精度计时，记录会话准备、开售等待、购买入口、票档、数量、观演人和提交阶段耗时。自动提交开启时记录首次提交耗时；关闭时记录到达订单确认页的耗时。

## 异常处理

- 配置或缓存错误：启动早期失败，不进入开售等待。
- 开售按钮等待超时：记录未出现可购买按钮，不点击预约，不重建会话。
- 数量或观演人校验失败：停止后续提交。
- 提交入口失败：返回失败并提示到大麦 App 核对实际订单状态。
- 提交前发生 WebDriver 会话异常：按外层上限重建会话；达到上限后失败。
- 提交后发生任何异常：不自动重试，明确提示订单结果未知并到大麦 App 核对。
- 所有路径均保留“页面状态不代表订单结果，需在大麦 App 确认”的现有提示。

## 测试与验证

先增加失败测试，再实现功能：

- 配置接受有效本机时间、拒绝无效类型/日期/时区，并完成保存回读。
- 空时间和过去时间不等待，未来时间等到目标点后继续，长等待按 60 秒间隔保活。
- 可购买检测拒绝预约、不可点击和不可用按钮，使用 100ms 轮询，超时期间不点击。
- 普通点击使用元素 ID，不读取元素坐标。
- 数量无法确认或不符时阻止购买和提交。
- 普通业务失败不重建会话，提交前 WebDriver 异常按上限重建，提交后异常不得再次提交，并最终关闭驱动。
- 现有票档、观演人、自动提交、API 和桌面 worker 测试保持通过。

实现后运行项目现有安卓相关测试和完整测试命令；实际启动仅安卓 Web 控制台，检查开售时间字段、保存、回显和空时间启动链路。没有已授权安卓设备及合适演出页面时，仅进行模拟驱动验证，并明确真机元素文本、数量读取、开售按钮状态和完整订单链路未验证。

## 已确认决策

- 采用定时门槛、页面状态检测和局部等待，不新增独立调度服务。
- 用户选择加入定时开售，而非仅保持手动启动。
- 到点后按钮仍不可买时等待可购买状态，不立即点击预约。
- 开售等待使用 100ms 轮询和 30 秒上限。
- 空开售时间保持立即执行。

# Scrcpy 实时按钮翻转感知设计

## 目标

用持续视频帧替代“u2 主动截图 → 整轮 OCR”的串行感知，压缩大麦 Canvas 自绘购买按钮的状态感知延迟。只有正面确认底栏出现“立即预订／立即购票／立即购买”才允许放行，未变化、未知或识别失败时不盲点“已预约”。

## 已确认方案

采用 Scrcpy server 通过 ADB 推送 H.264 画面，Mac 端用 PyAV 解码。固定 server 版本并随应用附带，不依赖用户额外安装 Scrcpy。现有 u2 截图＋OCR 保留为降级路径。

## 数据流

1. 开抢前启动 Scrcpy，完成 server 部署、视频解码和 OCR 预热，不把初始化放进关键路径。
2. 按屏幕底部购买栏区域裁剪视频帧；相邻帧先做低分辨率灰度差异比较，未超过阈值时不执行 OCR。
3. 区域变化后优先使用可用按钮模板做正面匹配；未配置模板或匹配不确定时，只对裁剪区域执行常驻 RapidOCR。
4. 命中白名单购买文案后立即停止视频流并交回现有点击流程。模板命中也必须位于购买栏区域。
5. 到开售时刻仍未命中时继续感知，在有限售后窗口内等待真实按钮翻转；超时或所有感知手段不可用时停止，不退回纯定时盲点。
6. Scrcpy 启动、解码或读取异常时回退 u2 截图＋OCR，仍执行相同的购买文案白名单。

## 组件与依赖

- 新增轻量 Scrcpy 视频接收模块，只实现部署、握手、H.264 解码和关闭，不引入旧的 Python Scrcpy 客户端依赖。
- 新增 `av` 运行依赖；图像处理复用现有 NumPy、Pillow、OpenCV/RapidOCR 环境。
- Scrcpy server 使用官方发布文件并记录来源、版本和校验值；PyInstaller 与 DMG 构建必须包含该文件及动态依赖。
- 第三方声明补充 Scrcpy、PyAV/FFmpeg 及所用图像组件许可证。

## 日志与计时

日志区分 Scrcpy 模板命中、Scrcpy OCR 命中、u2 OCR 命中和降级原因。放行日志以目标开售时刻为基准，负值表示提前、正值表示延后，避免售后命中被错误记录为零偏差。

## 验证

- 使用合成视频帧验证：未变化不 OCR、变化后正面命中、已预约/未知文案不放行、模板优先及 OCR 降级。
- 使用假客户端验证：Scrcpy 异常回退 u2、到点不盲点、售后超时停止、视频流在命中和异常后关闭。
- 保留并更新现有精准定时、页面跳转和单次提交测试。
- 真机只读验证视频帧与识别，不自动提交订单；无连接设备时明确标记未完成真机验证。

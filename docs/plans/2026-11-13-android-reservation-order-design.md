# 安卓纯预约快路设计

## 目标

仅支持已在大麦 App 完成预约的演出。开售后的客户端流程压缩为“立即购买 → 确认页轻量校验 → 立即提交”，不再执行城市、场次、票档、数量加号、观演人姓名或坐标识别。目标是减少本地操作耗时，不承诺服务器锁单时间。

## 已确认方案

采用方案 B：只支持原生预约快路，不提供通用识别回退。用户须提前在大麦 App 登录，完成目标场次、票档和观演人的预约，并停在目标演出详情页。

## 主流程

1. 创建 Appium 会话并保留大麦现有登录态和页面数据。
2. 精确查找并点击一次“立即购买”。未开售、按钮未出现或页面不明确时停止，不使用模糊文本替代点击。
3. 等待订单确认页出现，读取页面金额、观演人复选框和提交按钮。
4. 金额必须能解析为大于零的数字；已勾选观演人数必须等于配置的 `ticket_count`。不识别姓名，不更改预约选择。金额仅做有效性检查并写入日志，无法据此证明场次或票档正确。
5. 自动提交关闭时停在确认页。开启时，先记录提交尝试，再精确点击一次“立即提交”或“提交订单”。
6. 点击购买后发生任何异常均停止，不重新执行流程，不自动重发提交。

## 配置与界面

- 保留 Appium 地址、设备名、Android 版本、购票数量和自动提交开关。
- 移除安卓页面中的城市和票档序号输入；旧配置字段可继续读取，但不参与预约快路。
- 页面明确提示先完成大麦原生预约，预约内容以 App 为准。
- 移除未接入的 ADB 坐标快路、布局采集及性能探测代码；历史实现保留在 `master` 提交中。

## 安全限制

- 页面、金额或观演人数不符合预期时禁止提交。
- 提交尝试在点击前记录，进程内不得重复提交。
- 不自动重试整个抢票流程，避免订单状态未知时重复下单。
- 真机验证保持自动提交关闭，真实提交由用户另行控制。

## 验证

- 测试立即购买的精确定位和单次点击。
- 测试金额无效、观演人数不足或多余、确认页缺失时均不提交。
- 测试自动提交关闭、提交成功、点击异常和重入保护。
- 验证安卓配置兼容、前端语法及相关单元测试。
- 真机只验证到订单确认页，核对预约票档、数量和观演人是否自动带出。

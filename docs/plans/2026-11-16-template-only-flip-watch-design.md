# 无 OCR 按钮模板感知设计

## 目标

极速模式彻底移除按钮感知关键路径上的 OCR。Scrcpy 像素差分只决定是否检查画面，只有正面匹配“立即预订／立即购票／立即购买”模板才允许点击；任何未知、未确认或异常状态都不盲点。

## 已确认约束

- 不接受倒计时、动画或其他像素变化导致的误点。
- 不使用“已预约图像消失”作为可购买证明。
- 模板不存在、置信度不足或全部帧超时时停止，不回退 OCR，也不回退纯定时。
- 普通模式的页面识别暂不重写。

## 数据流

1. 开抢前启动 Scrcpy，读取已校准的正面按钮模板；没有模板则明确报错。
2. 第一帧及后续购买栏区域发生明显变化时，执行多尺度模板匹配；未变化时直接处理下一帧。
3. 只有模板分数达到阈值才放行。倒计时、动画和“已预约”等未知画面不匹配正面模板，因此不点击。
4. 命中后停止视频流并进入现有点击链路。售后等待超时或识别异常时停止。
5. 极速模式不再执行 OCR 预热，提交后不再截图 OCR 记录页面。

## 模板校准

复用现有安卓校准入口：用户先在大麦中打开一个已经显示可购买按钮的详情页，校准时从已定位的购买按钮区域裁剪灰度模板到配置所在目录的 `flip-templates/`。模板只代表正面可购买状态，不采集“已预约”作为放行条件。

开发源码与打包应用都使用各自配置所在目录，打包应用因此写入用户数据目录而不是只读 app bundle。模板目录作为内部配置 `flip_template_dir` 传给 worker；未配置时才尝试随包 `resources/flip-templates/`。

## 日志与错误

日志明确区分“模板命中”“模板缺失”“匹配超时”。模板缺失属于启动前配置错误，不能等到开售后再回退 OCR。模板命中日志保留相对目标开售时刻的提前或延后时间。

## 验证

- 未变化帧不执行匹配，变化帧才执行。
- 倒计时、已预约及未知图像不匹配模板，永不点击。
- 正面模板命中立即放行，整个极速感知过程不调用 OCR。
- 模板缺失、匹配超时和视频异常均停止且不点击。
- 校准只保存可购买按钮模板，不保存已预约模板。
- 提交后不再调用截图 OCR；现有定时、页面跳转与单次提交保护保持通过。

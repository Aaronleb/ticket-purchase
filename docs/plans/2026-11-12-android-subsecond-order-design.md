# 安卓一秒下单快速通道设计

## 目标与口径

目标是从首次票档点击到提交指令发出，在布局有效、页面响应正常的设备上争取 1 秒以内。服务器锁单和网络响应不属于客户端可保证的耗时。没有完整缓存或校验失败时使用现有安全慢路径，不承诺慢路径耗时。

## 已确认方案

1. 开售前建立 Appium 会话，采集票档、数量、确定购买、前 N 位观演人和提交按钮坐标，缓存与屏幕尺寸绑定。
2. 准备阶段预设并读取数量，快速通道不再逐个点击数量加号。
3. 开售前启动常驻 ADB Shell，避免每次点击都新建 ADB 进程；关键路径不执行 OCR、截图、XPath 或控件属性读取。
4. 票档、确定购买和观演人使用缓存坐标。观演人按索引前 N 位，不使用姓名匹配。
5. 提交指令独立发送，发送前做一次轻量页面与勾选人数校验。提交最多发送一次，失败不得盲点或自动补点。
6. 使用 `PerfRecorder` 记录各阶段和 Appium 命令耗时，分别报告准备耗时与首次点击后的关键路径耗时。

## 安全限制

- 坐标缓存必须完整且屏幕尺寸一致，否则整体降级。
- 提交前的页面或人数校验失败时禁止提交。
- 快速通道中途结果不明确时停止，不直接重复整串操作。
- 自动提交关闭时只执行到订单确认页，不发送提交。
- 真机验证先保持自动提交关闭；真实提交由用户另行确认。

## 验证

- 坐标缓存完整性、屏幕尺寸和缺失控件测试。
- 常驻 ADB 命令生成、点击顺序、延迟和失败测试。
- 前 N 位观演人坐标选择、数量预设和提交独立发送测试。
- 无缓存降级、校验失败不提交、重复提交保护测试。
- 完整单元测试、前端语法检查和 DMG 独立启动验证。

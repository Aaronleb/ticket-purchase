# Android SDK 环境修复设计

## 问题

DMG 应用只把内置 ADB 所在目录加入 `PATH`，没有设置 `ANDROID_HOME` 或 `ANDROID_SDK_ROOT`。Appium UiAutomator2 创建会话时要求至少一个变量存在，因此在操作大麦 App 之前退出。设备连接和用户配置不是本次故障原因。

## 方案

保留现有 `runtime/android-platform-tools` 目录结构。在应用启动时，将 `ANDROID_HOME` 和 `ANDROID_SDK_ROOT` 都设置为该目录的绝对路径，同时保留现有 `PATH` 配置。Appium 会继承这些变量，并从该目录直接定位 `adb`。抢票 worker 也继承同一环境，不需要单独修改配置格式或页面。

不引入完整 Android SDK，不要求用户安装或配置环境。

## 错误处理

启动时继续检查内置 Appium；SDK 环境配置只引用应用内固定路径，不覆盖为其他外部路径。若 ADB 文件缺失，现有 ADB 检查和 Appium 会话错误仍在控制台及日志中报告。

## 验证

1. 单元测试确认启动环境包含两个 SDK 变量、内置 ADB 路径及原 PATH。
2. 现有控制台测试和原安卓脚本测试继续通过。
3. DMG 验证确认 Appium 实际收到两个 SDK 变量，且仍可在无全局 Node、ADB、Appium 的环境启动。
4. 替换 `/Applications/DamaiAndroid.app` 后，用已授权的小米手机创建并关闭一次真实 Appium 会话。只允许会话初始化和读取当前页面，不点击购买、提交订单或支付。

## 发布

重新生成 `dist/DamaiAndroid-arm64.dmg`，更新校验值和使用文档中的真机验证状态。原配置和观演人数据继续保存在用户数据目录，不随应用替换删除。

## 票档页入口补充

真机验证发现大麦当前版本可能已经进入 `NcovSkuActivity` 票档页。该页有票档容器，但没有详情页的城市和预约按钮。脚本启动时先检测票档容器：存在则跳过城市和预约步骤，直接选择票档；不存在则沿用原详情页流程。该改动不改变观演人、票档序号和自动提交设置。

小米手机还需允许 Appium Settings 的“后台弹出界面”权限，否则重建会话时辅助 Activity 无法进入前台。该权限由用户在系统页面手动授权，应用不静默修改。

## 观演人勾选与提交保护

订单确认页的姓名文本不是可靠的勾选目标。脚本改为定位姓名所在行的 `cn.damai:id/checkbox`，仅在未选中时点击，并重新读取 `checked` 状态。任一观演人未找到或未勾选成功，主流程立即返回失败，不执行提交。只有全部观演人确认选中后，才根据 `if_commit_order` 决定是否提交。

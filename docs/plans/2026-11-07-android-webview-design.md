# 大麦安卓抢票独立窗口设计

## 目标

将现有本地 Web 控制台嵌入 `DamaiAndroid.app` 的独立 Mac 窗口。用户双击应用后直接看到控制台，不再自动打开默认浏览器，也不需要知道回环地址和端口。

本设计替换 `2026-11-07-android-dmg-design.md` 中“启动后打开默认浏览器”的交互，其余安卓抢票、内嵌依赖、配置和安全边界保持不变。

## 已确认的行为

- 使用 pywebview 和 macOS 系统 WKWebView，复用现有 HTML、CSS、JavaScript 与 Python 服务。
- 不引入 Electron、Qt WebEngine 或另一套前端。
- 点击窗口红色关闭按钮时完全退出应用，不停留后台。
- 从 Dock 退出和收到终止信号时，执行与关闭窗口一致的清理。
- 保留无窗口模式，供 DMG 自动化验证使用。

## 架构与生命周期

macOS 主线程负责创建和运行 WebView。现有 HTTP 服务改为后台线程运行，Appium 仍由 `AppiumService` 管理。服务就绪后，窗口加载仅绑定 `127.0.0.1` 的随机端口地址。

启动顺序：

1. 准备用户目录、内嵌工具和可写 Appium Home。
2. 启动 Appium 和本地控制台。
3. 默认创建“大麦安卓抢票”独立窗口；无窗口模式继续等待外部请求。
4. 进入统一的应用运行与退出流程。

退出顺序：

1. 停止 HTTP 服务，避免继续接收新任务。
2. 通过现有 `ProcessManager` 停止抢票 worker。
3. 停止 Appium 并关闭 HTTP 监听 socket。
4. 返回进程退出码。

清理集中在同一个 `finally` 路径，避免窗口关闭、信号退出和启动异常产生不同结果。macOS 原生退出请求由应用委托转换为窗口关闭，避免 `NSApplication` 直接终止而绕过 Python 清理；委托在主窗口完成初始化后安装并保持引用。页面桥接初始化尚未完成时，关闭请求先等待初始化结束再继续，避免 WKWebView 回调消失后遗留非守护工作线程。

## 依赖与打包

在构建依赖中固定 pywebview 版本，由 PyInstaller 收集 macOS 所需的 PyObjC/WKWebView 组件。最终应用继续内嵌全部运行依赖，用户不需要安装 Python 包。

更新第三方许可说明、DMG 构建产物和 README。应用仍为 Apple 芯片专用、临时签名且未公证，本改动不改变这些限制。

## 异常处理

- WebView 无法创建或加载时记录 `console.log`，清理后台进程并返回失败。
- Appium 启动失败时在窗口中展示失败状态和日志位置并禁止抢票；控制台无法启动时直接清理退出。
- 无窗口模式不导入或启动图形事件循环，保证自动化验收可在后台执行。
- 关闭窗口只退出本应用的子进程，不影响用户其他程序。

## 验证

- 单元测试覆盖默认窗口启动、无窗口模式、窗口关闭清理及 WebView 启动失败清理。
- 保留现有完整控制台测试和原项目安卓测试。
- 重新构建 DMG，检查应用架构、签名和内嵌 WebView 依赖。
- 从实际 DMG 运行无窗口模式，验证控制台、Appium、ADB、配置写入与退出清理。
- 从实际应用启动真实 WKWebView，确认窗口显示现有控制台且关闭后进程退出。
- 不通过测试提交真实订单；真机抢票仍单独验收。

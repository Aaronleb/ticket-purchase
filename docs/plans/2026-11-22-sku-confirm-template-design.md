# 票档页「确定」按钮模板感知 + Web 总价 设计与实施计划

日期：2026-11-22
状态：已实施（待真机校准）

## 0. 已确认的决定

1. 0.4 秒从**票档页首帧**开始计时，页面加载时间不计入；
2. 模板在**真机票档页**采集，不用附件做临时模板；
3. 总价**只展示 + 打日志**，不写配置、不参与运行时判断。

## 1. 目标

1. Web 控制台的安卓配置里增加「票档单价 + 预计总价」，开抢前一眼确认这场要花多少钱。
2. 为票档页（`NcovSkuActivity`）的「确定」按钮单独生成一张固定区域模板。
3. 票档页出现后，用 Scrcpy 帧监听「确定」按钮：模板命中且按钮已着色（可用）就立刻点击；
   **0.4 秒内没命中就直接按原坐标点击**，不让感知失败拖慢下单。

这一步不读取金额，也不与「我的预约」金额做运行时比对。金额只作为 Web 展示和日志。
原因见第 3 节：按钮左侧的价格块宽度会随金额变化，把它裁进模板会让模板失效。

## 3. 模板生成规则

新增模板：`sku-confirm.png`（与 `buy.png`、`negative-*.png` 同目录）。

裁剪规则：

1. 只裁按钮本体，**不包含价格块**；
2. 以右下角为锚点：右边距约 2.5%W，宽度约 36.6%W；
3. 纵向只要按钮本体：约 93.6%~98.1%H（避开底部手势条）；
4. 灰度保存，尺寸约 446×122（1220×2712 设备）。

裁剪来源与时机：

- 在校准流程里采集：手机停在票档页时，点「采集当前页按钮坐标」；
- 复用现有 OCR 找到「确定」中心，然后用**以该中心为基准的固定裁剪框**，
  不用 `_save_button_template` 的通用 0.18W/0.035H（会带进价格块和多于按钮的背景）；
- 同时把 OCR 中心写回 `confirm_point`（修正现在偏上的坐标）。

兼容性：

- 加载时按前缀区分：`buy*.png` 只给详情页用，`sku-confirm*.png` 只给票档页用，
  `negative-*.png` 继续做负向模板。避免详情页 watcher 把「确定」模板当成「立即购买」正面模板。
- 匹配沿用现有多尺度（0.5~2.0），覆盖 Scrcpy 帧（720×1600）与模板（446×122）的缩放差。

## 4. 运行时流程

### 4.1 视频流生命周期

现状：`flip_watch.make_scrcpy_watcher()` 在放行返回时 `stream.stop()`，票档页没有帧可用；
重新起流要 ~0.9 秒（实测），收益直接归零。

改为会话级：

- 开售前 30 秒启动，一直活到「立即提交」结束；
- `make_scrcpy_watcher(..., keep_alive=True)` 返回 watcher，并把 `stream` 暴露给 bot；
- `run_ticket_grabbing` 的 `finally` 统一关流（成功、超时、异常都关）。

### 4.2 票档页判断（0.4 秒）

设 `SKU_CONFIRM_WAIT = 0.4`：

1. 点底栏后，`_tap_buy_bar_until_next_page()` 已通过 logcat 拿到 `NcovSkuActivity` 的 START；
2. 保留 `_wait_drawn("NcovSkuActivity")`（事件感知通常几十毫秒，拿不到时最多 1.2 秒兜底）；
3. 从「首帧已绘制」开始计时，循环读 Scrcpy 最新帧：
   - 裁右下角固定按钮框；
   - 模板命中 + 按钮区高饱和（`_button_is_enabled`）→ 立刻点击 `confirm_point`，结束；
   - 模板文件缺失 → 直接走兜底，不阻塞；
4. 超过 0.4 秒仍未命中 → **直接点击 `confirm_point`**（用户要求的兜底）；
5. 后续逻辑不变：等 `DmOrderActivity` 最多 2 秒，仍在票档页才补点一次。

日志与计时：

- 命中：`票档页「确定」模板命中（+xxx 毫秒）`，`_mark("票档页模板命中")`；
- 兜底：`票档页 0.4 秒内未命中模板，直接点击「确定」`，`_mark("票档页兜底点击")`；
- 计时面板新增这两段，便于判断模板是否真的有用。

### 4.3 Web 总价

安卓配置卡片新增：

- 「票档单价」输入框（写回现有 `price` 字段，例如 `1299` 或 `1299元`）；
- 「预计总价」只读展示：解析单价数字 × 购票数量，实时更新（例如 `¥2598`）；
- 单价为空时显示「未填单价」；
- 启动日志打印一行：`预计总价 ¥2598（1299 × 2）`，与票档页的金额人工对照。

本轮不把总价用于运行时判断，也不引入 OCR。若后续要严格核对金额，
用之前讨论的方案 A：确认页出现后后台线程 `uiautomator dump` 读金额，与总价比对，
与现有 0.4 秒 settle 重叠，不占关键路径。

## 7. 测试计划

模板与裁剪：

- 用合成帧验证：价格从 ¥480 改成 ¥1080、¥1288 时，按钮裁剪区域像素完全一致；
- 验证裁剪不包含价格块（左边界在 60%W 之后）；
- 加载分流：详情页 watcher 不会加载 `sku-confirm.png`。

运行时：

- 0.1 秒命中模板 → 只点一次「确定」，日志是「模板命中」；
- 0.4 秒未命中 → 只点一次「确定」，日志是「兜底点击」；
- 模板缺失 / 视频流异常 → 不抛错，直接盲点；
- 流在提交后、超时后、异常后都被关闭；
- 仍然只补点一次，进确认页后绝不补点。

Web：

- 单价 1299 × 2 张 → 显示 `¥2598`；
- 单价为空 → 显示「未填单价」；
- 修改数量/单价实时联动；
- 保存后 `config.jsonc` 的 `price` 正确。

真机验收：

1. 打开任意**正在售票**的演出，进入票档页；
2. 点「采集当前页按钮坐标」，确认生成 `sku-confirm.png`、`confirm_point` 约为 (960,2613)；
3. 用「演练（不提交）」跑一次，日志应出现「票档页模板命中」或「兜底点击」，并成功进确认页；
4. 在「已预约」详情页再跑一次，确认负向模板仍拒绝放行；
5. 不提交真实订单。

## 8. 风险

| 风险 | 处理 |
|---|---|
| 模板来自不同分辨率/大麦版本 | 多尺度匹配 + 0.4 秒兜底，最坏退化为现在的盲点 |
| 价格块变宽压到按钮 | 目前票价位数最多 4~5 位，价格块右边界约 39%W，与按钮 60%W 起有安全间距；模板裁剪再留 5%W 余量 |
| 0.4 秒太短，慢机基本走兜底 | 可接受：兜底就是现有逻辑；后续可按真机数据调到 0.5~0.6 秒 |
| 长按/双击风险 | 仍然只点一次；只有「仍在票档页」才补点一次 |
| 保持视频流增加耗电 | 提交完成/超时/异常立即关流，最长只多活几秒 |
| 现有确定/提交坐标偏上 | 本次必须先真机校准；校准后写入 `confirm_point` / `submit_point` |

## 9. 实施顺序

1. 修正坐标：真机票档页校准，写回 `confirm_point`、`submit_point`；
2. 模板：校准流程生成 `sku-confirm.png`，加载分流；
3. 运行时：会话级流 + 0.4 秒监听 + 兜底；
4. Web：单价/总价 + 校准提示；
5. 测试与真机演练（不提交）。

# 内场票档 OCR 自动选择设计

## 目标

软件自动识别票档，不要求用户手工预选或输入票档序号。目标规则为：排除缺货票档，在内场中选择价格最高的可购买票档。自动提交订单仍由独立开关控制。

## 识别方案

使用本地 RapidOCR，不上传手机截图。Appium 读取票档容器和可点击卡片的位置，并对当前手机页面截图。OCR 文字按坐标归入各卡片，结合控件中的缺货标签，提取区域、价格和库存状态。

项目当前没有 OCR 依赖，需要加入 RapidOCR 及其 ONNX 运行时，并在 PyInstaller 中包含模型文件。该方案可复用于 macOS 和 Windows，不使用云 OCR。

## 选择与安全

1. 准备阶段只执行一次 OCR，过滤包含“内场”的卡片，识别价格并按数值降序缓存候选顺序。OCR 不进入开售后的关键点击路径。
2. 正式选择时读取轻量控件，排除缺货、售罄、无票、缺票及不可点击的卡片，直接使用缓存位置点击当前最高可购买价位。
3. 最高价位失效时按缓存顺序尝试下一档，不重新执行 OCR。页面结构变化、候选失效或结果不明确时停止，不回退到手工序号。
4. 点击目标卡片后重新读取页面合计价格，与目标价格不一致则停止，不进入购买按钮步骤。
5. 日志列出准备阶段识别到的候选和正式选择目标，但不把 OCR 结果或进程退出当作订单成功依据。

## 配置与兼容

新增票档区域和价格策略配置，默认“内场”和“最高可购买价位”。保留旧配置字段的读取兼容，但新流程不使用票档序号作为失败回退。Web 页面展示区域和策略，替代容易误解的序号输入。

## 验证

- 单元测试覆盖区域过滤、缺货过滤、最高价选择、无候选和歧义。
- 使用真机只读 OCR 分析，确认识别文字、卡片映射和候选排序。
- 自动提交关闭时验证目标卡片选择与价格核对，不点击最终提交。
- 运行原项目和控制台测试，重新构建 DMG，验证 OCR 模型在独立应用中可用。

# ticket-new 安卓网页控制台设计

## 目标

在现有本地 Web 控制台中加入安卓平台，复用 `ticket-purchase/damai_appium` 的 Appium 抢票能力，形成配置、环境检查、启动、日志和停止的完整操作流程。保留现有 PC 功能。

## 范围

- 用户启动前在大麦 App 中手动登录，并打开目标演出详情页。
- 安卓配置包括 Appium 地址、设备名、Android 版本、城市、票档序号、观演人和自动提交开关。
- Appium 服务由用户根据页面提示手动启动，本版不由控制台管理 Appium 后台服务。
- 真实订单结果以大麦订单记录为准，不把进程结束或按钮点击视为购票成功。

## 方案

增强并复用现有 `damai_app_v2.py`，避免复制两套安卓抢票逻辑。修正设备参数固定和自动提交开关未生效的问题。直接启动原脚本会继承这些问题，复制脚本则会增加后续维护和不一致风险，因此不采用。

## 架构与数据流

- `ticket-new` 后端增加安卓配置读写、环境检查和启动接口。
- 安卓配置写入 `ticket-purchase/damai_appium/config.jsonc`，保留原脚本所需但本流程不使用的字段。
- 启动命令使用当前 Python 解释器执行 `damai_app_v2.py`，工作目录为 `damai_appium`。
- 复用现有 `ProcessManager` 的子进程、进程组停止、内存日志和状态快照能力，以及现有 SSE 日志与状态推送。
- PC 与安卓任务共用单任务锁，避免同时操作浏览器和手机造成状态混淆。
- 原 Appium 脚本从配置读取设备名、Android 版本和 Appium 地址；仅在 `if_commit_order` 为真时点击提交订单。

## 页面

- 增加 PC / 安卓平台切换，按平台显示对应表单与账号/设备说明。
- 安卓页面不显示 PC Cookie 登录态，改为展示设备与 Appium 环境状态。
- 配置、状态、实时日志、自动提交二次确认和停止操作沿用现有交互。
- 页面明确提示：提前登录并打开目标详情页、票档序号从 0 开始、Appium 服务需提前启动。

## 环境检查与错误处理

分别检查：

- 当前 Python 环境是否安装 Appium 客户端。
- Appium 服务地址是否可访问并返回就绪状态。
- ADB 是否可用、配置的设备是否在线。
- 设备是否安装 `cn.damai`。

检查失败时返回具体、可操作的错误，不启动抢票。配置写入继续采用原子替换；接口保留本机请求标识和现有输入校验。

## 测试与验证

- 为安卓配置校验、配置读写、接口路由、启动命令和工作目录增加单元测试。
- 为自动提交开关及设备参数传递增加不依赖真实设备的测试。
- 使用模拟安卓任务验证页面配置、启动、日志、状态和停止闭环。
- 运行项目现有完整测试。
- 若当前环境连接了安卓设备，再执行环境检查；未连接设备时明确保留真机流程验证项。

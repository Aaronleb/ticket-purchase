# 安卓购票数量与观演人选择设计

## 目标

安卓端支持独立预设购票数量，并按数量选择观演人列表中的前 N 位，不再按姓名逐个匹配。数量与观演人勾选状态必须一致，否则停止后续购买或提交。

## 已确认方案

1. 新增 `ticket_count` 配置，默认 1，控制台允许设置 1–6 张。旧 `users` 配置继续读取，但安卓流程不再使用它推断票数或匹配观演人。
2. 票档页沿用现有限量控件，通过“＋”将默认 1 张调整为预设数量。
3. 确认购买页一次读取观演人行，只保留前 N 行勾选；如果后续行已勾选则取消，避免实际人数超过票数。
4. 操作后重新读取所有复选框，确认前 N 行已选且选中总数等于 N。
5. 观演人不足、控件读取失败、点击后状态不符合预期或总数不一致时返回失败，主流程不得点击最终提交。
6. 保留“自动提交订单”开关，关闭时仍停在订单确认页。

## 兼容与边界

- 老配置没有 `ticket_count` 时使用 1，不再根据旧 `users` 数量推断，以保证行为明确。
- 观演人列表少于 N 时失败，不自动减少票数。
- 列表多于 N 时取消多余勾选，避免全选导致超量。
- 真机控件结构以现有 `layout_main`、`text_name`、`checkbox` 资源 ID 为基础，不引入坐标硬编码。

## 验证

- 配置默认值、合法范围及旧配置读取。
- 数量 1 时不点击“＋”，数量 N 时点击 N−1 次。
- 前 N 位选择、已有勾选、取消多余勾选、人数不足及状态校验失败。
- 校验失败时不进入购买或提交步骤。
- 运行原项目和控制台回归测试；真机验证时保持自动提交关闭。

## 2. 时钟基准（重要）

日志与实测：

- 本机 - 手机 = **-989.9ms**（手机比本机快约 0.99 秒）；
- 本机 - 服务器 = **-182.8ms**（服务器比本机快约 0.18 秒）；
- 手机比服务器快约 **807ms**；
- 放行目标按手机会被提前到 `12:59:59.010`，服务器真实开售是 `12:59:59.817`；
- 底栏翻转检测在 `13:00:00.045`，**相对服务器开售只晚约 228ms**；
- 提交在 `13:00:01.446`，**相对服务器开售约 1.63 秒**。

结论：日志里的「开售后 1.020 秒放行」是相对手机对齐目标的口径，不是服务器；
真正需要优化的是 **228ms 翻转延迟 + 1.40s 后链路**，不是那 1 秒。

## 3. 已实施优化

### P0 确认页固定 0.4 秒 → 「立即提交」模板命中即点

- 先用后台线程跑 `uiautomator dump` 的方案验证：真机确认页一次 dump **超过 3 秒**，
  不能放进关键路径，已放弃；
- 最终方案：确认页首帧后监听 Scrcpy 帧里的 `sku-submit.png` 模板，命中且按钮着色
  就立刻点击；最多等 0.4 秒，超时按原逻辑补足稳定时间后盲点；
- `sku-submit.png` 在确认页校准「立即提交」时自动生成（固定按钮框，不含金额）；
- 模板未命中通常说明按钮还是**禁用态**（观演人未选/数据未加载），这比盲目点击安全；
- 后台 dump 方法保留为诊断用途（`_wait_confirm_ready`），不在极速路径调用。

### P1 翻转感知提速与诊断

- Scrcpy `max_fps` 15 → **30**，开售瞬间帧间隔 66ms → 33ms；
- 模板命中时打印 `score / scale / 开售后毫秒数`；超时打印最高分，
  用于判断延迟来自 App 刷新还是模板匹配；
- 开售后首次正面命中时，后台保存当前按钮为 `buy-live.png`（只存一次），
  下一次开抢同时加载预售态与开售态模板，减少匹配等待。

### 时钟口径

- 同时测量手机与服务器偏差，偏差 >150ms 且服务器偏差来自 **NTP** 时，
  **改用服务器时钟**放行；只有 HTTP Date 时仍用手机时钟，避免 CDN 过期时间；
- 日志同时打印两个偏差、采用的基准，以及相对该基准的开售延迟；
- 手机与服务器接近时仍用手机时钟（大麦倒计时渲染以手机为准）。

## 4. 未实施：Scrcpy 控制通道点击

实测三次 `adb shell input tap` 在面板里都只有 **1ms** 级（常驻 shell），
控制通道注入最多省几十毫秒，但要实现 scrcpy 2.4 的坐标固定点协议，
风险与收益不成比例，暂不做。

## 5.1 真机 5 次演练结果（2026-11-22，崔健天津预售页，未提交）

| 次数 | 票档页确定模板 | 确认页首次模板 | 补选观演人后 | 有效路径* |
|---|---:|---:|---:|---:|
| 1 | 347ms | 401ms 未命中 | 59ms 命中 | 1.38s |
| 2 | 248ms | 404ms 未命中 | 85ms 命中 | 0.96s |
| 3 | 340ms | 407ms 命中 | — | 1.38s |
| 4 | 301ms | 403ms 未命中 | 55ms 命中 | 1.02s |
| 5 | 303ms | 432ms 命中 | — | 1.42s |

有效路径平均 **1.23s**（原实战 1.40s），测试页首次确认页模板多数因按钮禁用而走满 0.4 秒。

\* 有效路径已扣掉测试脚本手动选票档的 2 秒左右，只算真实点击链路。

说明：

- 5/5 都进入了确认页，**0 次提交**；
- 测试页没有预约观演人，首次「立即提交」按钮是禁用态，模板正确地没有放行；
  手动补选观演人后模板 55~85ms 命中，证明生效；
- 正式场次预约会带出观演人，按钮从首帧起就是可用态，预期提交模板 50~100ms 命中，
  可省掉原来 0.4 秒稳定等待；
- 票档页「确定」模板稳定在 248~347ms，0.4 秒预算基本够用，再缩短会误伤慢帧。

其中 0.62s 票档页 + 0.29s 确认页属于大麦页面跳转，客户端无法压缩。
不采用「提前打开票档页预热」：会重置票档选择，风险大于收益。

## 6. 验证

- 单元测试：确认页后台读取成功/超时/异常、金额与观演人警告、提交只点一次；
- 时钟：手机/服务器接近用手机、偏差过大用服务器、手机失败退回服务器；
- 模板：命中分数统计、开售态模板只存一次、Scrcpy 默认 30fps；
- 真机：连续 5 次演练（不提交），比较面板耗时和 `submit_verified`；
- 正式场次前确认票档/观演人已由预约带出，演练不提交订单。

## 7. 前端「预热票档页」按钮（2026-11-22）

控制台安卓端新增按钮：**预热票档页（2 次）**。

使用方式：

1. 先打开一个**非目标**演出的详情页（目标详情页留在上一页）；
2. 点按钮；
3. 程序自动：点底栏打开原生票档页 → 返回详情页，重复 2 次 → 再退一页；
4. 结果会显示每次打开票档页的耗时和最终页面。

安全边界：

- 底栏检测到「已预约 / 票档已选好」直接拒绝，避免重置目标场次的票档；
- 只做导航，不选票档、不点「确定」、不下单；
- 当前不是详情页、或票档页没有打开（H5 引导页）时给出明确提示，不会反复乱点；
- 从票档页返回后等 0.6 秒再点下一次，避免详情页过渡期点空。

实测（崔健天津预售页）：

- 按钮预热 2 次：**161ms / 197ms**；
- 同样页面冷态首次打开：**383 / 404ms**；
- 原生票档页连续热态打开：**74~101ms**。

注意：如果目标详情页不在上一页，预热完成后会退回频道/首页，程序会提示手动返回；
票档页的预热效果不受影响。
